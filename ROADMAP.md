# Project Roadmap

> **Project owner:** h4ckd4d

## Vision

Transform **Shodan Dorks for Advanced OSINT** from a query reference into a professional defensive framework for **Internet Exposure Intelligence**, **External Attack Surface Management (EASM)**, **OSINT**, and **Cyber Threat Intelligence (CTI)** workflows.

The project is intentionally defensive. It focuses on discovery, attribution, enrichment, classification, prioritization, validation, and reporting for assets that are owned, administered, or explicitly authorized for assessment.

## Operating model

```text
Discover
  ↓
Attribute
  ↓
Enrich
  ↓
Classify
  ↓
Analyze Exposure
  ↓
Prioritize Risk
  ↓
Validate
  ↓
Report
  ↓
Track Remediation
```

## Phase 1 — Professional foundation

- Structured query collections.
- Official-filter validation.
- Documentation quality CI.
- Defensive-use policy.
- Project governance and ownership attribution.
- Machine-readable catalog.

## Phase 2 — Exposure intelligence framework

- Asset-attribution methodology.
- Ownership-confidence model.
- Exposure taxonomy.
- Analyst playbooks.
- Risk-prioritization model.
- JSON schemas for scope, assets, and findings.
- Structured service/technology catalog.

## Phase 3 — Scope-aware tooling

- Local CLI for generating queries from an approved scope file.
- Query linting and scope validation.
- Normalized asset records.
- Export formats for analyst workflows.
- Baseline-versus-observed comparison model.

## Phase 4 — Multi-source enrichment

Planned defensive correlation patterns:

- Shodan
- DNS
- Certificate Transparency
- RDAP / WHOIS
- Censys or equivalent Internet telemetry
- Internal CMDB / cloud inventory

The goal is correlation and validation, not automated interaction with third-party systems.

## Phase 5 — Intelligence engineering

- Temporal analysis.
- Certificate clustering.
- Infrastructure relationship graphs.
- Confidence scoring.
- Exposure trend reporting.
- Detection of inventory drift and shadow IT.

## Core analytical rule

> Observation ≠ Finding ≠ Vulnerability ≠ Exploitability ≠ Compromise

Every stage requires its own evidence and validation.
