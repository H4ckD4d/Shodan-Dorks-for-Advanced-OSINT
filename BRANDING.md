## Usage

The canonical signature is intended for Markdown documentation, analyst playbooks, methodology documents, project governance documents, technical references, and generated Markdown reports.

Machine-readable JSON schemas, data fixtures, source-code files, configuration files, CI workflows, and the MIT license should remain structurally clean. Those files may contain concise ownership metadata where appropriate, but they should not receive the full Markdown signature block.

## Consistency rules

- Always write the project handle as `h4ckd4d` in lowercase in branding copy.
- Use `Chris Cruz | h4ckd4d` as the owner identity line.
- Preserve the exact tagline: `Protect. Detect. Defend.`
- Do not alter credential wording in the canonical signature without owner approval.
- External contributors receive contributor credit without changing project ownership attribution.
